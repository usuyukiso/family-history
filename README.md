# Семейная история — онлайн-книга

Прототип сайта на MkDocs Material. Спецификация проекта — `genealogy_site_spec.md`.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/mkdocs serve        # http://127.0.0.1:8000
.venv/bin/mkdocs build --strict   # проверка: падает на битых ссылках и неизвестных ID
```

## Структура

- `docs/people/P1000-….md` — страница человека (ID `P`).
- `docs/places/PLC1000-….md` — страница населённого пункта (ID `PLC`).
- `docs/sources/archives/A1000-….md` — архивная запись (`A`), `books/` — книги (`B`), `documents/` — документы и сканы (`D`).
- `docs/assets/documents/scans/` — PDF и сканы для публикации.
- `hooks/id_links.py` — превращает ссылки по ID в настоящие ссылки.
- `hooks/family_tree.py` — строит родословное древо на странице «Родословное древо» (`docs/tree.md`) из полей `parents`, `spouses`, `children` в front matter (вставляется вместо `<!-- family-tree -->`) и то же древо — в левом меню в разделе «Персоны». Подпись в меню берётся из `nav`; страница, которой в `nav` нет, всё равно появится в меню с подписью «год имя».

## Как писать ссылки

Пишите только ID, путь к файлу знать не нужно:

| В тексте | На сайте |
|---|---|
| `[A1006]` | ссылка «A1006» на страницу источника, при наведении — его название |
| `[P1000]` | ссылка с именем человека |
| `[жена](P1000)` | ссылка со своим текстом |

ID берётся из начала имени файла (`A1006-giaso-….md`). Хук превращает его в относительный путь
(`../sources/archives/A1006-….md`), а MkDocs — в адрес страницы. Поэтому base url в текстах не нужен:
сайт одинаково работает локально, на `ЛОГИН.github.io/family-history/` и на своём домене.

Новый ID: следующий свободный номер с нужной буквой, номера не переиспользуются.
Новую страницу нужно добавить в `nav` в `mkdocs.yml`.
